# Port a lint rule from another linter

Rules keep their origin in `sources` of `declare_lint_rule!`, and `docs/reference/rule_sources.md` (generated by `just gen-lint`) lists the source of every rule. A rule is ported when its id appears there; search `RuleSource::<Linter>("<id>")` in `crates/pgls_analyser/src` to find the rule.

## Get the source

Clone the linter into the repository root, where `.gitignore` keeps it out of commits:

| Linter | Clone | Rules | `sources` |
| --- | --- | --- | --- |
| [Squawk](https://github.com/sbdchd/squawk) | `squawk/` | `crates/squawk_linter/src/rules/`, one file per rule with its tests | `RuleSource::Squawk("ban-drop-column")` |
| [Eugene](https://github.com/kaaveland/eugene) | `eugene/` | `eugene/src/lints/rules.rs`; id, name, effect and workaround in `eugene/src/hint_data.rs`; bad and good SQL in `eugene/examples/<id>/` | `RuleSource::Eugene("E11")` |
| [pgfence](https://github.com/flvmnt/pgfence) | `pgfence/` | `src/rules/`, described in `RULES.md` | `RuleSource::Pgfence("drop-trigger")` |

## Port

1. Check for an existing rule that reports the same thing, under another name too (Squawk's `ban-drop-column` is `banDropColumn`, Eugene's E3 is `preferJsonb`). If one does, extend it if the source covers more, and add the source to its `sources` instead of adding a second rule.
2. Port the whole behaviour: full lists (e.g. every non-volatile function), every statement form the source matches, and its tests as spec files. Port the tests that must not report too.
3. Translate the source's AST to ours. Squawk uses libpg_query too, so the nodes match `pgls_query::protobuf`; Eugene matches a simplified `StatementSummary`, so map each variant to the Postgres nodes (`AlterTableStmt` → `AlterTableCmd` → `ColumnDef`, ...). What the source reads from its options or other statements comes from the context here: the server version from the catalog, earlier statements through the catalog and session (`ctx.catalog()`, `ctx.session()`), the transaction from `ctx.in_transaction()`.
4. Write the diagnostic in our style: what is wrong, why, and what to do instead (see the pillars in `crates/pgls_analyser/CONTRIBUTING.md`). Don't copy the source's text verbatim.
5. If the context lacks something the rule needs, don't approximate the rule. Stop and report what is missing.

## Not ported on purpose

- Squawk's opt-in rollback compatibility rules (`ban-add-column`, `ban-revoke`, `ban-drop-index`, `ban-set-default`, `ban-create-policy`, ...), which report most schema changes.
- Squawk rules that rules from pgfence and Eugene already cover: `ban-drop-schema`, `ban-drop-trigger`, `ban-disable-trigger`, `require-concurrent-reindex`, `require-concurrent-partition-detach`, `require-timeout-settings` and `prefer-repack`.
